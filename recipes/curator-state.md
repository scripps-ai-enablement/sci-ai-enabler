# Curator state

## Recently surfaced

- **Fit a dose-response curve and report a defensible IC50** (added 2026-08-02) — rung-2 [Dose-Response Analysis skill](../catalog/tools/tooluniverse-dose-response.html) recipe closing the cookbook's most conspicuous assay-analysis hole: SAR, QSAR, synergy and ADMET recipes all *consume* potency numbers and nothing produced one. Long-format `doseresponse_input.csv` with **replicates kept as separate rows, never pre-averaged** (pooling first destroys the inter-experiment variance that is the actual uncertainty) → committed `.claude/commands/fit-dose-response.md` so the next plate is analysed by the same text → per-replicate 4PL fit emitting IC50 + CI, Hill slope, Emax/Emin, r², and `plateau_reached` → **`rejected_curves.csv` with a reason string and no IC50 at all** for non-monotonic/biphasic data, r² < 0.90, or neither plateau reached; one-plateau curves marked `approximate, extrapolated` rather than rejected → **truncated-window AUC emitted alongside IC50**, window fixed in the command file → `summary.csv` carrying geometric-mean IC50 *with min/max across replicates*, never a bare pooled number → potency comparison gated on both curves r² ≥ 0.95 with concordant slopes → `provenance.json` (ToolUniverse version, skill commit SHA, input sha256, control definition, AUC window, r² gate, model id). Drug Repurposing and Discovery focus-day recipe; cross-linked as the upstream of [score-drug-combination-synergy](items/score-drug-combination-synergy.html) (which explicitly needs single-agent potency and had no source for it). `Proposed` — the skill is not benchmarked end-to-end, but each rule traces to a result: truncated-range sigmoid AUC beat IC50/EC50/full-range AUC for cross-platform *and* cross-version agreement across pharmacogenomics screens ([Chen et al., *Bioinformatics* 2026](https://pubmed.ncbi.nlm.nih.gov/42286248/)) — the basis for step 4; point "best fit" values understate uncertainty, hierarchical fitting recovers inter-experiment variability ([Johnstone et al. 2016](https://doi.org/10.12688/wellcomeopenres.9945.2)) — the basis for the replicate-spread rule; monotonic sigmoids fail on biphasic resistance curves and discard biologically significant observations ([Zhang et al. 2013](https://doi.org/10.1371/journal.pone.0069301)) — the basis for the rejection gate. Deliberately declared **no new dependency**: plotting is left to whatever the project already pins, rather than shipping an unverified pin. `Fully open` and fully local (no structure or assay result leaves the machine — usable on unpublished internal screens), `Laptop`.
- **Source purchasable compounds for a hit list** (added 2026-08-02) — rung-2 [Chemical Sourcing skill](../catalog/tools/tooluniverse-chemical-sourcing.html) recipe covering the step between a ranked hit list and a plate, which the cookbook skipped entirely (hits were filtered, ADMET-profiled, and docked, then silently assumed to exist): `hits.csv` keyed on **SMILES not name** with `intended_assay` per row so the purity floor is derived per compound (≥95 screening / ≥98 dose-response / ≥99 reference standard) → committed `.claude/commands/source-compounds.md` → `sourcing.csv` **one row per listing, not per compound**, with `price_per_mg` normalized and `in_stock` / `make_on_demand` never collapsed → four exception files treated as first-class results, read *before* the main table: `smiles_mismatch.csv` (the one that costs a whole experiment), `no_source.csv` (a publishable reason a top-ranked hit was never tested), `missing_purity.csv`, `price_outliers.csv` (>5× median per mg ⇒ probable different salt form) → `analogs.csv` at Tanimoto ≥ 0.7 kept strictly separate, because an analog changes the hypothesis the model scored → `provenance.json` with the **UTC query date** foregrounded (prices/stock/lead times are the most perishable data in the cookbook). Drug Repurposing and Discovery focus-day recipe; cross-linked downstream of [filter-virtual-screening-hits](items/filter-virtual-screening-hits.html) (both ways) and [enumerate-analogs-around-a-lead](items/enumerate-analogs-around-a-lead.html), and to the new dose-response recipe as the assay whose ≥98% floor step 3 protects. `Proposed` — skill unbenchmarked, but both design axioms are measured: Tox21 analytical QC over >13,000 sample identifiers found only **76% of gradeable samples exceeded 90% purity** and **11% degraded after four months in DMSO** ([Richard et al., *Chem Res Toxicol* 2025](https://doi.org/10.1021/acs.chemrestox.4c00330)) — why purity is a gate, not a footnote; and **>97% of core Bemis–Murcko scaffolds in make-on-demand libraries are absent from in-stock collections** ([Irwin et al., *JCIM* 2020](https://doi.org/10.1021/acs.jcim.0c00675)) — so filtering to in-stock is a chemical-space decision, not logistics. `Fully open` on licence but the **disclosure caveat is stated as the real access bar**: query SMILES leave the machine to commercial vendors, and no offline substitute exists or can exist, because the data lives in the vendors' inventories. `Laptop`, API-bound, batch in chunks of a few dozen against rate limits.
- **Handle missing endpoint data in a confirmatory trial** (added 2026-08-02) — rung-2 [Missing Data Sensitivity skill](../catalog/tools/missing-data-sensitivity.html) recipe opening the clinical-biostatistics leg of the cookbook, which was entirely empty (protocol *design* was covered by [draft-phase23-clinical-trial-protocol](items/draft-phase23-clinical-trial-protocol.html), the primary-endpoint *analysis* by nothing): estimand written to `analysis/estimand.md` **before any method is chosen**, with a strategy named per intercurrent event (discontinuation and rescue usually need different ones) → missingness profile by arm and visit, Little's MCAR test reported but explicitly barred from licensing MAR → **MMRM in R `mmrm` with unstructured covariance and Kenward–Roger df, `statsmodels.mixedlm` forbidden as confirmatory** (no KR correction), with the SAP's covariance-fallback hierarchy recorded when unstructured fails to converge → `rbmi` reference-based family (JR/CR/CIR) run *together*, never one pick → **both Rubin's and frequentist variances as side-by-side columns** rather than a silent choice → tipping point emitted in residual-SD units → `provenance.json` carrying the RNG seed (MI is stochastic; without it the sensitivity table is not reproducible). Translational Medicine focus-day recipe. `Proposed` — no agent-driven attempt documented, but every step traces to a specific result: JR/CR/CIR are special cases of a potential-outcomes causal model and varying its assumption *is* the tipping point ([White, Joseph & Best 2020](https://doi.org/10.1080/10543406.2019.1684308)); reference-based MI is information-anchored, which is why Rubin's variance is reported and not replaced ([Cro, Carpenter & Kenward 2019](https://doi.org/10.1111/rssa.12423)); the δ- and reference-based tutorial the workflow follows ([Cro et al. 2020](https://doi.org/10.1002/sim.8569)); and required `m` grows *quadratically* with FMI, not linearly — the "5–10 imputations is fine" advice covers point estimates only ([von Hippel](https://doi.org/10.1177/0049124117747303)). `Fully open` with a copyleft flag (`mice`/`mitools` GPL-2; `mmrm`/`rbmi` Apache-2.0) and an explicit note that a laptop run is the *specification* a validated environment reproduces, not the submission run. `Laptop`, with `rbmi` jackknife × `m` × tipping grid named as the binding cost.
- **Define a phenotype cohort in an OMOP CDM database** (added 2026-08-02) — rung-3 pairing of [OMOPHub MCP](../catalog/tools/omophub-mcp.html) + [pyomop](../catalog/tools/pyomop.html), the first recipe to touch the OMOP/OHDSI leg: vocabulary release pinned via `list_vocabularies` **first** (concept ids are stable, hierarchy membership is not) → concept set built by querying, with the instruction *do not state a concept_id you have not retrieved from the server* as the guardrail against the characteristic silent failure (a confidently-recalled wrong concept id runs cleanly and returns the wrong cohort) → non-standard ICD-10 mapped to standard SNOMED with both sides shown → `concept_set.csv` with a **per-concept** `include_descendants` flag plus a committed `concept_set_excluded.csv` (a reviewer's first question is always about a code you left out) → schema inspected before SQL is written (v5.3 vs v5.4 produce valid-but-wrong queries) → `check_sql` before `run_sql`, read-only DB role required since pyomop does not restrict `run_sql` upstream → **attrition table, not a count** (a step dropping 0% or 100% is a join bug, not a finding) → fixed sanity panel → bundle shipped to collaborating sites instead of row counts. Neuroscience focus-day recipe; cross-linked to [sort-spikes-from-neuropixels-recording](items/sort-spikes-from-neuropixels-recording.html) (the neural side to align against), [localize-implant-tip-in-brain-atlas-subregion](items/localize-implant-tip-in-brain-atlas-subregion.html) (histology for the same animal), and the new calcium recipe. `Proposed` — no agent-driven attempt documented and the skill text is AI-generated, but the components are hard-validated: SuperAnimal covers 45+ species with no new labels, excellent on six benchmarks, 10–100× more data-efficient when fine-tuned ([Ye et al., *Nat Commun* 2024](https://doi.org/10.1038/s41467-024-48792-2)) — the basis for the zero-shot-first ordering; median error 0.228 cm = 2.0% of ROM against XROMM subcutaneous markers in marmosets ([Moore et al., *J Exp Biol* 2022](https://doi.org/10.1242/jeb.243998)) and mm-range agreement against Fastrak ([Kosourikhina et al., *PLOS ONE* 2022](https://doi.org/10.1371/journal.pone.0276258)); and the step-3 diversity rule is measured, not folklore — 25%-participant models held for adult joint angles but failed on clinical parameters and toddlers where 75% models reached good-to-excellent ICC against Vicon ([Verhoeven et al., *J Biomech* 2025](https://doi.org/10.1016/j.jbiomech.2025.112708)). `Fully open` (skill MIT, DeepLabCut LGPL-3.0, nothing leaves the machine — matters for identifiable human video), `Workstation with GPU` (training is the binding cost; the zero-shot path skips it).
- **Extract neuronal traces from a calcium imaging movie** (added 2026-08-02) — rung-2 [Calcium Imaging Analysis Guide skill](../catalog/tools/calcium-imaging-analysis-guide.html) recipe closing the second uncovered Neuroscience skill and the imaging half of the population-activity problem: raw two-photon or miniscope movie → **preparation declared up front, because every rule in the skill branches on it** (CNMF-E for one-photon/miniscope where out-of-focus background dominates vs CNMF/sparse-NMF/Cellpose for two-photon; non-rigid for awake behaving vs rigid for anesthetized; max shift ~10% FOV) → committed `extract_traces.py` with **neuropil subtraction before dF/F, not after**, and `R_NEUROPIL` / baseline percentile / window as named constants → `roi_qc.csv` (SNR, skewness, compactness, classifier score) plus `rejected_rois.csv` **with a reason string per rejection, treated as part of the result** → ROI-footprint overlay on mean/max projections inspected *before* the trace heatmap (segmentation failures are obvious there and invisible downstream) → deconvolution as a separate, optional, differently-named output labelled an estimated firing rate, never overwriting dF/F → `provenance.json` (package + version, motion-correction method and max shift, ROI algorithm params, every QC cutoff, kept/rejected counts, input sha256, model id). Neuroscience focus-day recipe; cross-linked with the new pose recipe and the Neuropixels sorting recipe as the two routes to the same population matrix. `Proposed` — assembly undocumented, skill text AI-generated, methods strong: CaImAn near-human ROI detection against multi-labeler annotations on nine two-photon datasets ([Giovannucci et al., *eLife* 2019](https://doi.org/10.7554/eLife.38173)); CASCADE trained on >35 h / 298 neurons of paired ground truth, infers *absolute* rates and beats model-based deconvolution, self-retraining to the unseen data's rate and noise ([Rupprecht et al., *Nat Neurosci* 2021](https://doi.org/10.1038/s41593-021-00895-5)), with later supervised nets improving on the same database ([Zhou et al. 2023](https://doi.org/10.1016/j.crmeth.2023.100462)) — the justification for step 5's separation; downstream classifiers >80% correct but with differing FP balance and perturbation sensitivity ([Ananthamurthy & Bhalla, *eNeuro* 2023](https://doi.org/10.1523/ENEURO.0007-22.2023)), the argument for recording extraction parameters. Recipe explicitly tells the reader to re-derive the AI-generated thresholds (r ≈ 0.7, 8th–20th percentile / 30–60 s, SNR > 3, skewness > 0.5), flagging the neuropil coefficient as the one that shifts every correlation in the dataset. `Fully open` with a copyleft note (Suite2p GPL-3.0, CaImAn GPL-2.0; CaImAn is conda-only), `Workstation with GPU` where RAM/NVMe are the real limits, not VRAM.
