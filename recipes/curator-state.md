# Curator state

## Recently surfaced

- **Analyze the SAR of a measured compound series** (added 2026-07-19) — rung-2 [SAR Analysis skill](../catalog/tools/sar-analysis.html) recipe: CSV of assayed analogs (`smiles` + IC50/Ki) → optional [datamol](../catalog/tools/datamol.html) standardization → MCS scaffold detection + R-group decomposition (RDKit `rdFMCS`/`rdRGroupDecomposition`) → per-R-position substituent-vs-pIC50 table → single-change activity-cliff flagging (|ΔpIC50| ≥ 1) → committed `sar_analysis.py` + pinned `requirements.txt` + `sar_table.csv`/`activity_cliffs.csv` + aligned-structure HTML report + `provenance.json` (RDKit/pandas versions, skill commit, MCS threshold, cliff cutoff, input sha256, run date, model id). Drug Repurposing and Discovery focus-day recipe; retrospective *analyze-what-you-measured* sibling of the forward [enumerate-analogs](items/enumerate-analogs-around-a-lead.html) recipe (cross-linked both ways). `Reported` — R-group decomposition + matched-pair single-substituent comparison are field-standard for lead optimization ([Raut & Dixit, *RSC Med. Chem.* 2025](https://pubmed.ncbi.nlm.nih.gov/40438290/); [Ding et al., *Curr. Med. Chem.* 2020](https://pubmed.ncbi.nlm.nih.gov/32338210/); [Kombo & LaMarche, *J. Med. Chem.* 2025](https://pubmed.ncbi.nlm.nih.gov/40418162/)) and the BixBench-evaluated skill calls validated RDKit routines; the Claude-driven path is not separately benchmarked. Note: the skill does single-position R-group comparison, not a full MMP transformation network (`mmpdb`-class tool absent from the catalog). `Fully open`, `Laptop`.
- **Diagnose a rare disease from patient phenotypes** (added 2026-07-19) — rung-2 [ToolUniverse Rare Disease Diagnosis skill](../catalog/tools/tooluniverse-rare-disease-diagnosis.html) recipe: patient HPO terms (+ optional candidate variants) in a committed `case.yaml` → skill federates HPO/Orphanet/OMIM/DisGeNET disease+gene lookup → gene prioritization (MARRVEL, ClinGen validity, GTEx tissue expression) → per-variant ACMG interpretation (ClinVar, gnomAD, EVE/SpliceAI) → tiered (T1–T4) `reports/*.md` + raw `results/*.json` audit trail + `provenance.json` (tooluniverse version, skill commit, per-database query dates, ClinVar/gnomAD release accessions, input sha256, model id). Translational Medicine focus-day recipe; phenotype-first sibling of [interpret-clinical-variant](items/interpret-clinical-variant.html) (cross-linked both ways). `Reported` — knowledge-grounded LLM layers over the same MARRVEL/ClinVar/gnomAD tool stack give +12–15 pp Recall@1 for phenotype-driven gene prioritization ([LA-MARRVEL, Lee et al., *arXiv* 2511.02263, 2025-11 / rev 2026-03](https://arxiv.org/abs/2511.02263)); tool grounding carries the workflow (MARRVEL-MCP 95% vs 33%, [bioRxiv 2025-11-28](https://www.biorxiv.org/content/10.1101/2025.11.26.690887v1)); rung-1 fails (database-free GPT-4 ~16%, [Kim et al., 2024](https://arxiv.org/abs/2403.14801)); the exact ToolUniverse-skill composition is not separately benchmarked. `Fully open`, `Laptop`.
- **Build a resting-state functional-connectivity matrix from preprocessed fMRI** (added 2026-07-19) — rung-2 [Nilearn skill](../catalog/tools/nilearn-tool.html) recipe: fMRIPrep-preprocessed BOLD + confounds → named atlas (Schaefer 2018) `NiftiLabelsMasker` (standardize/detrend/band-pass) → explicit fMRIPrep confound strategy → ROI time-series with confounds regressed → Pearson + partial-correlation ROI-to-ROI matrices → network-ordered heatmap + FD/scrubbing QC → committed `build_connectome.py` + pinned `requirements.txt` + `connectivity_pearson.csv`/`connectivity_partial.csv` + figure + `provenance.json` (Nilearn version, atlas name/release, confound columns, band-pass/TR, connectivity kind, input sha256s, run date, model id). Neuroscience focus-day recipe; fMRI counterpart to the EEG [extract-event-related-potentials-from-eeg](items/extract-event-related-potentials-from-eeg.html) sibling (cross-linked). `Reported` — Nilearn is the field-standard connectivity library ([Abraham et al., *Front. Neuroinform.* 2014](https://doi.org/10.3389/fninf.2014.00014)); atlas→confound-regression→correlation workflow is canonical ([Kumar et al., *PLoS Comput. Biol.* 2020](https://doi.org/10.1371/journal.pcbi.1007549)) and reused across current rs-FC studies ([Messina et al., *Neurology* 2026](https://doi.org/10.1212/WNL.0000000000214656); [Dai et al., *J. Affect. Disord.* 2026](https://doi.org/10.1016/j.jad.2025.120969)); the Claude+Nilearn-skill assembly is not separately benchmarked. `Fully open`, `Laptop`.
- **Integrate multi-omics layers into interpretable factors with MOFA+** (added 2026-07-18) — rung-2 [MOFA+ skill](../catalog/tools/mofaplus-multi-omics.html) recipe: 2+ omics views on the same samples/cells ([muon](../catalog/tools/muon-multiomics-singlecell.html)/MuData for single-cell multi-modal, AnnData dict for bulk) → per-view feature selection → build + train MOFA+ model (`mofapy2`, fixed factor count + seed) → per-factor per-view variance decomposition → factor–metadata association → top loadings → committed `mofa_run.py` + pinned `requirements.txt` + `mofa_model.hdf5` + variance/association/loading CSVs + figure + `provenance.json`. Molecular and Cellular Biology focus-day recipe; cross-modality factorization complement to the within-modality [scVI batch-integration recipe](items/integrate-single-cell-datasets.html), distinct from batch integration (different modalities, not different batches). `Proposed` — no documented Claude+MOFA+-skill attempt; grounded on the canonical method ([Argelaguet et al., *Genome Biology* 2020](https://doi.org/10.1186/s13059-020-02015-1)) and a current applied exemplar (12-factor MOFA+ over 667 TCGA gliomas, prognostic factor validated across n=1685 without retraining; [Saleh et al., *Cancers* 2026](https://doi.org/10.3390/cancers18101652)). `Fully open`, `Laptop`.
- **Design amino-acid sequences for a fixed protein backbone** (added 2026-07-18) — rung-3 two-model toolbelt: [ProteinMPNN skill](../catalog/tools/proteinmpnn.html) samples sequences for a target backbone `.pdb` (fixed catalytic/interface positions, temperature sweep) → [ESMFold skill](../catalog/tools/esmfold.html) refolds each design → self-consistency gate (Cα-scRMSD < 2.0 Å AND mean pLDDT > 80) keeps only foldable candidates → ranked survivors → committed `.claude/commands/mpnn-design.md` + pinned skill envs + `designs/*_mpnn.fasta` + `results/*_selfconsistency.csv` + `provenance.json`. Integrative Structural and Computational Biology focus-day recipe; first to compose the ProteinMPNN family, cross-linking [LigandMPNN](../catalog/tools/ligandmpnn.html)/[SolubleMPNN](../catalog/tools/solublempnn.html) variants, [AlphaFold2](../catalog/tools/alphafold2.html) as a stricter second gate, and the [score-protein-variants-with-esm](items/score-protein-variants-with-esm.html) sibling. `Reported` — ProteinMPNN is the field-standard inverse-folding model ([Dauparas et al., *Science* 2022](https://doi.org/10.1126/science.add2187)), the design→refold→filter self-consistency routine is standard, and a ProteinMPNN redesign of a flavin-binding fluorescent protein was wet-lab confirmed ([Nikolaev et al., *Protein Sci.* 2024](https://pubmed.ncbi.nlm.nih.gov/38501498/)); the Claude-skill assembly is not separately benchmarked. `Fully open`, `Workstation with GPU`.

## Missing components

- **Constrained-retrosynthesis agent (LARC-style Agent-as-a-Judge)** — the new [plan-a-synthetic-route-for-a-target-molecule recipe](items/plan-a-synthetic-route-for-a-target-molecule.html) uses the [CovaSyn MCP](../catalog/tools/covasyn.html) `covaplatform` retrosynthesis tool for unconstrained route search, then post-filters for simple constraints. Search-time enforcement of hard constraints (reagent-class avoidance, reaction whitelist, step-count ceiling) via an in-loop constraint judge — the design that lifts [LARC](https://arxiv.org/abs/2508.11860) to 72.9% on 48 constrained tasks — needs a Claude-installable agentic-retrosynthesis framework. None is a skill/MCP/plugin today. Would unlock a constrained-route sibling recipe. Surfaced 2026-07-18.
- **Trained KG drug-repurposing model wrapper (TxGNN / COMIC / CellAwareGNN)** — the new [find-repurposing-candidates-in-a-knowledge-graph recipe](items/find-repurposing-candidates-in-a-knowledge-graph.html) uses the [PrimeKG skill](../catalog/tools/primekg.html), which exposes only neighbor lookups (`search_nodes`/`get_neighbors`/`get_disease_context`), so the recipe is an interpretable graph-traversal heuristic, not a learned link predictor. A Claude-installable wrapper around a trained GNN over PrimeKG — TxGNN (the canonical model), or the newer [COMIC](https://doi.org/10.1186/s12859-025-06337-4) (recovered 21/30 recent FDA repurposing pairs, +9.55% over SOTA) / [CellAwareGNN](https://pubmed.ncbi.nlm.nih.gov/42124589/) (AUPRC 0.826) — would unlock a calibrated *ranked-prediction* sibling recipe with far higher recall than the traversal heuristic. None is Claude-installable (skill/MCP/plugin) today. Surfaced 2026-07-12.
- **Colocalization / Mendelian-randomization driver (coloc / TwoSampleMR / SuSiE-coloc)** — the new [triage-gwas-hits-to-drug-targets recipe](items/triage-gwas-hits-to-drug-targets.html) uses [GWAS-MCP](../catalog/tools/gwas-mcp.html) for the lookup-and-annotate layer (variant consequence, eQTL-implicated gene, GWAS Catalog context, drug-target support), but stops short of *causal* inference. Establishing that a GWAS signal and an eQTL share a causal variant (colocalization) and the direction of effect (MR) — the steps that lift Lessard et al.'s approved-target enrichment from 1.75 to 2.58 ([*BMC Genomics* 2024](https://pubmed.ncbi.nlm.nih.gov/39563277/)) — needs summary-statistic-level statistical tools ([coloc](https://chr1swallace.github.io/coloc/), [TwoSampleMR](https://mrcieu.github.io/TwoSampleMR/)). Neither is Claude-installable (skill/MCP/plugin) today. Would unlock a causal-directional sibling recipe downstream of the GWAS triage. Surfaced 2026-07-12.
- **Local pH-aware protonation-state enumerator (Dimorphite-DL / OpenBabel `-p` / ChemAxon cxcalc)** — the new [prepare-protonation-states-for-docking recipe](items/prepare-protonation-states-for-docking.html) uses the [Rowan skill](../catalog/tools/rowan.html) `submit_macropka_workflow`, which runs cloud-side (SMILES leave the machine — a data-residency blocker for confidential structures). areas scientists actually compose against. Keep the last ~15 lines.
