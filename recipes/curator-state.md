# Curator state

## Recently surfaced

- **Compute 16S microbiome alpha/beta diversity from a BIOM table** (added 2026-06-02) — rung-2 [scikit-bio skill](../catalog/tools/scikit-bio.html) recipe taking a BIOM feature table + sample metadata + Newick tree through rarefaction → Shannon/Simpson/Faith's PD → weighted/unweighted UniFrac → PCoA → PERMANOVA with explicit grouping-column and permutation-count flags. First Immunology and Microbiology focus-day recipe of this run; cookbook's first dedicated microbiome / community-ecology recipe. `Proposed` evidence — no documented end-to-end attempt of this exact assembly. Closest class-level evidence: [Huang et al. *Biomni* (bioRxiv 2025.05.30.656746)](https://doi.org/10.1101/2025.05.30.656746) whose published benchmark includes microbiome disease-taxa bioinformatics across five datasets (HMP, MetaPhlAn2 human metagenomics, drinking-water OTU matrices) at ~4× over base-LLM accuracy.
- **Parse FCS flow-cytometry files for downstream immunophenotyping** (added 2026-06-02) — rung-2 [FlowIO skill](../catalog/tools/flowio.html) recipe taking a directory of vendor-emitted FCS 2.0/3.0/3.1 files through `FlowData` parsing → per-file metadata harvest (`$TOT`, `$CYT`, `$DATE`, panel keywords) → scatter/fluorescence/time channel categorisation → optional log/gain transforms → concatenated long-format events Parquet, with explicit failure surfacing for partial-acquisition files. Second Immunology and Microbiology focus-day recipe; cookbook's first cytometry / FCS recipe. `Proposed` evidence — no documented end-to-end attempt of this exact assembly. Closest class-level evidence: ["Enhancing Clinical Workflow Efficiency in Flow Cytometry Reporting with LLMs" (PMC13053331, *J. Clin. Immunol.* 2026)](https://pubmed.ncbi.nlm.nih.gov/?term=PMC13053331) demonstrates pathologist-level accuracy of fine-tuned LLMs on the *downstream* report-generation step the parsed-events output feeds into.
- **Convert raw analytical instrument data to Allotrope ASM JSON** (added 2026-06-01) — rung-2 [instrument-data-to-allotrope skill](../catalog/tools/instrument-data-to-allotrope.html) recipe taking a vendor-format file (cell counter, plate reader, HPLC, MS, qPCR) through auto-detect → `allotropy` native parse → ASM JSON-LD + flattened CSV + exportable Python parser, with strict-validation of the raw-vs-derived split before LIMS / data-lake handoff. First Chemistry focus-day recipe of the previous run; cookbook's first workflow-automation recipe spanning the Anthropic life-sciences plugin family. `Reported` evidence anchored in the [Claude for Life Sciences launch (October 2025)](https://www.anthropic.com/news/claude-for-life-sciences), the [Anthropic tutorial](https://claude.com/resources/tutorials/getting-started-with-claude-for-life-sciences) walking through a Vi-CELL example end-to-end, and the [`Benchling-Open-Source/allotropy`](https://github.com/Benchling-Open-Source/allotropy) reference parser the skill wraps.
- **Set up a protein molecular dynamics simulation in GROMACS from a PDB ID** (added 2026-06-01) — rung-2 [molecule-mcp](../catalog/tools/molecule-mcp.html) recipe driving the GROMACS Copilot server through topology → solvation → ion neutralisation → minimisation → NVT/NPT equilibration → production MD → RMSD/RMSF/Rg analysis, with explicit force-field / water-model / GPU-offload flags. Second Chemistry focus-day recipe; first cookbook entry exercising the GROMACS path of the molecule-mcp bundle. `Proposed` evidence — no documented end-to-end attempt of this exact assembly. Closest peer-reviewed class-level evidence: [MDCrow (Campbell et al., *Mach. Learn. Sci. Technol.* 2025, DOI:10.1088/2632-2153/ae4b07)](https://iopscience.iop.org/article/10.1088/2632-2153/ae4b07) — OpenMM-based but same agent architecture, demonstrates an LLM agent significantly outperforms plain LLM (t-test p=1×10⁻³) and ReAct (p=4×10⁻⁴) across 25 MD tasks; [DynaMate (arXiv:2512.10034)](https://arxiv.org/abs/2512.10034) extends to GROMACS protein-ligand; [NAMD-Agent (arXiv:2507.07887)](https://arxiv.org/abs/2507.07887); cautioned by [MDGym (arXiv:2605.08941)](https://arxiv.org/abs/2605.08941), which reports <21% completion on easy LAMMPS/GROMACS tasks for Claude Code / Codex / OpenHands.
- **Prioritize targets within a disease via Open Targets** (added 2026-05-31) — rung-2 [Open Targets plugin](../catalog/tools/open-targets.html) recipe taking a disease (EFO/MONDO) to a ranked target shortlist across the four prioritisation pillars (precedence, tractability, doability, safety) with cited GraphQL fields per cell. First Drug Repurposing and Discovery focus-day recipe of the previous run; complements the existing gene-in [Build a target dossier](../recipes/items/build-target-dossier.html) and disease-in/drug-out [Scan approved drugs for repurposing candidates](../recipes/items/scan-drug-repurposing-candidates.html) recipes. `Reported` evidence — the prioritisation framework is documented in [Buniello et al. *NAR* 53(D1):D1467–D1475 (2025)](https://doi.org/10.1093/nar/gkae1128) and informed by [Minikel et al. *Nature* 629:624–629 (2024)](https://doi.org/10.1038/s41586-024-07316-0); the MCP server inherits the same fields. Closest LLM-driven application: [Zunzunegui Sanz et al. *bioRxiv* 2025-06-13](https://doi.org/10.1101/2025.06.13.659527) and [More et al. *npj Precision Oncology* 10:95 (2025)](https://doi.org/10.1038/s41698-025-01265-1).
