# Curator state

## Recently surfaced

- **Medidata Connector** (added 2026-06-14) — `medidata@anthropics/life-sciences`, a Claude.ai Connector / Claude Code plugin wrapping Medidata's hosted HTTP MCP server (`https://mcp.imedidata.com/mcp`). Two clinical-operations services: **Platform Help** (query Medidata Knowledge Hub docs for Rave EDC / Data Connect / Clinical Data Studio; iMedidata login) and **Predictive Site Ranking** (rank clinical-trial sites by predicted enrollment during protocol planning; Intelligent Trials subscription). Surfaced on the Translational Medicine directed pass via the `anthropics/life-sciences` marketplace, where the `medidata/.claude-plugin/plugin.json` now publishes a concrete HTTP install path — this **resolves the long-standing deferred item** (previously gated behind Medidata account onboarding with no install path). Tagged Translational Medicine.
- **SpikeLab** (added 2026-06-14) — `braingeneers/SpikeLab` (MIT), a suite of computational-neuroscience agent skills for multi-electrode-array (MEA) spike-train data: **spikelab-spikesorter** (Kilosort2/Kilosort4/RT-Sort, unit curation, stim-aligned sorting, optional remote-Kubernetes offload), spikelab-analysis-implementer, spikelab-educator, spikelab-developer, spikelab-map-updater, plus a router skill. Skills ship inside the pip package at `spikelab/agent/skills/` (`pip install "spikelab[all]"`, copy into `~/.claude/skills/`); an optional built-in MCP server is available via the `mcp` extra (its `claude mcp add` snippet is not published upstream — page marks the stdio form `Unverified —`). Surfaced on the Neuroscience directed pass; tagged Neuroscience. bioRxiv preprint 2026-04-25.
- **scmcphub single-cell MCP siblings** (added 2026-06-13) — three sibling servers to the already-catalogued `scanpy-mcp` in the scmcphub ecosystem, surfaced on the Molecular and Cellular Biology directed pass: **LIANA-MCP** (`scmcphub/liana-mcp`, cell-cell communication over liana-py; tagged Immunology and Microbiology + Molecular and Cellular Biology), **decoupler-MCP** (`scmcphub/decoupler-mcp`, PROGENy pathway + CollecTRI TF activity; same tags), and **CellRank-MCP** (`scmcphub/cellrank-mcp`, cell-fate/trajectory via GPCCA; tagged Molecular and Cellular Biology). Each is `pip install <pkg>` → `<pkg> run` (stdio) / `--transport shttp` (HTTP), v0.4.0 (2025-06-27). License stated as BSD-3-Clause per the ecosystem (scmcp/scanpy-mcp confirmed BSD-3); per-repo LICENSE not separately confirmed — noted inline on each page.
- **protein-mcp-server (cyanheads)** (added 2026-06-13) — `cyanheads/protein-mcp-server` (Apache-2.0), a multi-provider structural-biology MCP orchestrating RCSB PDB + PDBe + UniProt with `protein_search_structures` / `protein_get_structure` / `protein_find_similar` / `protein_track_ligands` (+ `compare`/`analyze_collection` in development). `bunx protein-mcp-server@latest`; defaults to HTTP on port 3010, `MCP_TRANSPORT_TYPE=stdio` for Claude Desktop. Surfaced on the Integrative Structural and Computational Biology directed pass via the official MCP Registry. **Not a new page** — folded into the existing `pdb.md` as a third install option (one entry per data source — PDB/PDBe).
- **Human Protein Atlas MCP Server** (added 2026-06-13) — `Augmented-Nature/ProteinAtlas-MCP-Server` (MIT), a 14-tool stdio MCP server over the Human Protein Atlas: protein search, tissue/blood/brain expression, subcellular localization, cancer prognostic markers, batch lookup, and antibody validation/staining data. Install from source (git clone + `npm install`/`npm run build`; the server lives in the `proteinatlas-server/` subdir). Surfaced on the Immunology and Microbiology directed pass; tagged Immunology and Microbiology + Molecular and Cellular Biology + Translational Medicine (HPA is an antibody-based resource with cancer-pathology coverage).

## Flagged for review

- **OpenClaw-Medical-Skills** (`FreedomIntelligence/OpenClaw-Medical-Skills`) — flagged 2026-06-11 on a **license contradiction**, blocking batch ingest. The README markets it as "a curated collection of open-source medical and bioinformatics skills," but (a) there is **no LICENSE file** in the repo, and (b) **185 of 449 `SKILL.md` files carry a per-file proprietary header**: "All Rights Reserved. This code is proprietary and confidential. Unauthorized copying of this file, via any medium is strictly prohibited." (© 2026 MD BABU MIA, PhD, MSSM — "Universal Biomedical Skills" project). The remaining ~59 carry OSI license lines and the rest none. Generating "Free / OSS" catalog pages over a collection that is partly all-rights-reserved would be inaccurate and is not done. **Do not ingest** until upstream publishes a single coherent repo license (or per-skill licenses we can read programmatically). Note: most of OpenClaw's life-science surface (it shares many skill slugs with K-Dense/SciAgent — adaptyv, anndata, alphafold, arboreto, …) is already catalogued from the two cleanly-licensed collections, so the unique-coverage loss from deferring is small.
